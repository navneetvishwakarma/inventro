Primary action

Step 1: name + optional budget → Continue. Step 2: tap-select 3–8 shopping presets → Continue. Step 3: optional 60-second stock tick-off (~40 items, checkbox list) → Finish (or Skip).

Conditional / empty / loading states

Same card shell, body swaps per step: Step 2 replaces the two fields with a checkbox list of shopping presets (6–8 rows); Step 3 replaces it with a longer scrollable checkbox list (Skip + Finish buttons instead of Continue). Skipping step 3 is a fully supported path, not an error state.

Responsive behavior (web → mobile)

Identical narrow centered-card structure at both sizes; the wizard deliberately stays narrow even on the 1280 canvas rather than stretching full-width — wide empty margins either side on web are intentional, not unfinished.

Open structural questions & assumptions

To confirm before this moves to the visual design system pass.

  1. No global nav exists in the current code (explicitly noted in app/page.tsx). This deck proposes a 9-item web sidebar and a 5-slot mobile tab bar (Today / Inventory / Add / Shop / More) that folds Plan+Shopping List into one “Shop” tab and Review+Insights+Catalog+Settings into “More.” Confirm this IA before it's built, especially the Plan/Shopping-List merge.
  2. Should Review be a persistent nav destination at all, or purely notification-driven (reached only via the badge/link surfaced on Today)? It currently lives under “More” in this proposal.
  3. Inventory item detail: Used it up / Used some / Wasted currently sit high on the screen (matching the source). Should they move into the lower two-thirds for one-thumb mobile reach, or is top placement intentional so the actions are seen alongside the prediction explanation that justifies them?
  4. Review detail on mobile: for a grouped 2–3-image order, does the document preview need a swipeable thumbnail strip/carousel, or is a static stacked preview of all images sufficient?
  5. Catalog manager: this deck proposes a sticky bottom “Merge selected” bar on mobile once 2 items are picked (current source keeps it inline in the scroll). Confirm whether that ergonomic change is wanted.
  6. Shopping list's “nothing due in this selection” state is explicitly meant to read as good news, not a broken screen (per the UX journey doc) — does it need a distinct illustrated/reassuring treatment in the visual pass, beyond a plain text line?
  7. Onboarding wizard: confirmed as exactly 3 steps in one card shell with no preceding splash/welcome screen — confirm that's still correct before visual design locks in a step count.
  8. Insights and Settings are the lowest responsive-diff screens in this set (already a single narrow column at both sizes). Confirm that's acceptable, or whether mobile should get more aggressive defaults (e.g. category breakdown collapsed to top-3 + “show all”).
  9. Cost-meter severity (normal / approaching-limit / hard-stopped) is shown here via border weight and fill density only, since this pass is grayscale. Confirm that reads clearly enough, or whether it needs an icon/label in addition to color once the visual system is applied.
  10. Passcode gate has no “forgot passcode” or recovery affordance, matching the PRD's shared-passcode (not real auth) model for v1 — confirm that's still in scope as a deliberate non-goal.
